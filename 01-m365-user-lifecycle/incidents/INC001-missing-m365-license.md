# INC001 — New Starter Missing Microsoft 365 Licence## ScenarioA newly created user identity existed successfully in Microsoft 365 but did not have access to the licensed Microsoft 365 services expected for a normal employee.## ImpactSingle user.## Symptoms- User identity existed in Microsoft 365.- Account sign-in was permitted.- Licensed Microsoft 365 services were unavailable to the user.## Investigation1. Confirmed that the user identity existed under Active users.2. Verified that sign-in was not blocked.3. Reviewed the user's Licenses and apps configuration.4. Confirmed that Microsoft 365 Business Premium was not assigned.5. Verified that Business Premium licences were available in the tenant.## Root CauseThe user had a valid Microsoft 365 identity but no Microsoft 365 Business Premium product licence assigned.The identity itself was functioning correctly; the missing licence prevented entitlement to the licensed Microsoft 365 services.## Recommended ResolutionConfirm that the user requires Microsoft 365 Business Premium.If the technician is authorised to manage licence assignments:1. Verify that an appropriate licence is available.2. Assign Microsoft 365 Business Premium to the user.3. Allow sufficient time for the licence and associated services to provision.4. Verify that the required Microsoft 365 services are available to the user.If licence assignment requires additional approval or permissions, document the identified root cause and escalate the request through the appropriate organisational process.## Lab OutcomeThe account was intentionally left unlicensed so that it could continue to be used for licensing and troubleshooting exercises.No licence was removed from another working user.At the time of investigation, the tenant contained:- 25 Microsoft 365 Business Premium licences- 1 licence assigned- 24 licences available## VerificationThe investigation confirmed that:- The user identity existed.- Sign-in was permitted.- Microsoft 365 Business Premium was not assigned.- Business Premium licences were available in the tenant.Full licensed-service verification was not performed because the account was intentionally retained in an unlicensed state for further lab exercises.## ITSM Resolution Note**Symptom:** New starter unable to access expected licensed Microsoft 365 services.**Scope:** Single user.**Investigation:** Confirmed user identity existed and sign-in was permitted. Reviewed licence assignment and identified that Microsoft 365 Business Premium was not assigned. Confirmed that licences were available in the tenant.**Root Cause:** Missing Microsoft 365 Business Premium licence.**Recommended Action:** Assign an available Business Premium licence subject to organisational authorisation and verify service provisioning.**Status:** Root cause identified. Account intentionally retained as unlicensed for lab troubleshooting purposes.## Service Desk Principles Demonstrated- Confirm symptoms before assuming a cause.- Verify identity and account state before making changes.- Distinguish identity from product licensing.- Confirm licence availability before attempting remediation.- Avoid unnecessary changes to working users.- Perform changes only when authorised.- Escalate when required by permissions or organisational procedure.- Record only verified findings in ITSM documentation.- Verify the result after remediation.## Skills Demonstrated- Microsoft 365 Admin Center- User administration- Microsoft 365 licensing- Account-state verification- Root-cause analysis- Service Desk troubleshooting- ITSM documentation- Change-risk awareness- Escalation awareness
